# راهنمای نصب Campaign Loop (نسخه‌ی PHP 8.1 + MySQL)

این بسته، نسخه‌ی کامل و قابل‌اجرای محصول «حلقه‌ی کمپین» است: طراحی کمپین، ده دیدگاه، پیش‌بینی، پایش، ثبت نتیجه، علت‌یابی انحراف، کالیبراسیون نرخ‌ها، گزارش، دفترچه‌ی دیدگاه‌ها، تیم و نقش‌ها، ۲FA، پلن و پرداخت، اتصال ادتریس/اینترک، API سرور به سرور و لایه‌ی روایت هوشمند با **ChatGPT از طریق متیس**.

هیچ کتابخانه‌ی خارجی (Composer/npm) لازم نیست. همه‌چیز داخل همین پوشه است.

---

## ۱. پیش‌نیازها

| مورد | حداقل |
|---|---|
| PHP | ۸٫۱ یا بالاتر (روی ۸٫۱ تا ۸٫۴ آزموده شده) |

## ۲. نصب سریع (روش پیشنهادی: وارد کردن پایگاه داده)

۱. **آپلود:** فایل zip را در cPanel ← File Manager داخل `public_html` (یا یک زیرپوشه) آپلود و **Extract** کنید. محتوای پوشه‌ی `campaign-loop` باید در ریشه‌ی سایت قرار بگیرد (یعنی `index.php` مستقیماً در `public_html` باشد).

۲. **ساخت پایگاه داده:** cPanel ← MySQL® Databases:
   - یک Database بسازید (مثلاً `user_loop`)
   - یک User بسازید و با **ALL PRIVILEGES** به Database اضافه کنید.

۳. **وارد کردن جدول‌ها و داده:** cPanel ← phpMyAdmin ← پایگاه داده‌ی جدید را انتخاب کنید ← تب **Import** ← فایل `database/database.sql` ← **Go**.
   این فایل همه‌ی ۳۸ جدول، داده‌های مرجع (مناسبت‌ها، ضرایب صنعت، تنظیمات پیش‌فرض)، یک حساب مدیر و یک فضای کاری با داده‌ی دمو را می‌سازد.

۴. **اتصال:** آدرس سایت را باز کنید. چون `config.php` هنوز وجود ندارد، خودکار به `/install/` می‌روید. فقط بخش **پایگاه داده** (نام، کاربر، رمز) و **آدرس سایت** را پر کنید و «نصب» را بزنید. نصب‌کننده تشخیص می‌دهد جدول‌ها از قبل وارد شده‌اند و فقط `config.php` را با کلید رمزنگاری تصادفی می‌سازد.
   > بخش «حساب مدیر» در این حالت اختیاری است؛ اگر پر کنید، همان ایمیل و رمز جایگزین حساب پیش‌فرض می‌شود.

۵. **ورود:**
   - ایمیل: `admin@example.com`
   - رمز: `ChangeMe123`
   - در اولین ورود، سامانه شما را به تغییر رمز وادار می‌کند.

۶. **ایمنی:** پوشه‌ی `install` را از هاست **حذف کنید**.

۷. **کران‌جاب:** بخش ۴ را انجام دهید.

۸. **کلید متیس:** بخش ۵ را انجام دهید. (بدون کلید هم همه‌چیز کار می‌کند؛ متن‌ها از قالب‌های قطعی ساخته می‌شوند.)

تمام. یک حلقه‌ی کامل را با داده‌ی دمو در ۵ دقیقه امتحان کنید: «آماده‌سازی ← کمپین تازه ← طراحی ← ده دیدگاه ← پیش‌بینی ← پایش ← نتیجه ← کالیبراسیون ← گزارش ← بستن حلقه».

## ۳. روش‌های دیگر نصب

### الف) نصب‌کننده روی پایگاه داده‌ی خالی
مراحل ۱ و ۲ بالا، سپس بدون Import مستقیم `https://your-site/install/` را باز کنید و همه‌ی فرم (از جمله ایمیل و رمز مدیر و گزینه‌ی داده‌ی دمو) را پر کنید. جدول‌ها، حساب مدیر و `config.php` ساخته می‌شوند.

### ب) دستی، بدون نصب‌کننده
۱. `database/database.sql` را Import کنید.
۲. `config.sample.php` را به `config.php` کپی کنید و مقادیر `db` را پر کنید.
۳. در `app_key` یک رشته‌ی **۶۴ کاراکتری هگز تصادفی** بگذارید (مثلاً خروجی `php -r "echo bin2hex(random_bytes(32));"`) و در `cron_token` یک رشته‌ی تصادفی دیگر.
   > `app_key` کلید رمزنگاری کلید متیس، رمز SMTP و ۲FA است. بعد از راه‌اندازی **هرگز تغییرش ندهید**.

### نصب در زیرپوشه
اگر برنامه در `https://site.com/loop/` است، مقدار `base_url` در `config.php` را `https://site.com/loop` بگذارید. (نصب‌کننده خودش تشخیص می‌دهد.)

### هاست بدون mod_rewrite
اگر همه‌ی صفحه‌ها به‌جز صفحه‌ی اول خطای ۴۰۴ می‌دهند، در `config.php` مقدار `'pretty_urls' => false` بگذارید. آدرس‌ها به شکل `index.php?r=/login` ساخته می‌شوند و همه‌چیز کار می‌کند.

## ۴. کران‌جاب (زمان‌بندی)

در cPanel ← Cron Jobs، **هر ۱۵ دقیقه** (`*/15 * * * *`):

```
php /home/USERNAME/public_html/cron.php
```

اگر هاست cron خط فرمان ندارد، از آدرس وب استفاده کنید (توکن در `config.php` ← `cron_token` است):

```
wget -q -O /dev/null "https://your-site/cron.php?token=CRON_TOKEN"
```

کارهایی که cron انجام می‌دهد (هر کار فاصله‌ی اجرای خودش را دارد و اجرای مکرر بی‌خطر است):

| کار | توضیح |
|---|---|
| `connector_sync` | همگام‌سازی روزانه‌ی ادتریس/اینترک ← پایش تجمعی، هشدار عقب‌ماندگی، و پس از پایان کمپین + پنجره‌ی انتساب: **پیش‌نویس خودکار نتیجه** |
| `campaign_ending` | دو روز قبل از پایان کمپین: ایمیل و اعلان «نتیجه را ثبت کنید» |
| `awaiting_result` | کمپین تمام‌شده بدون نتیجه: اعلان «حلقه باز مانده» |
| `monthly_report` | ابتدای هر ماه شمسی: گزارش ماه قبل برای مالک و ناظر (با خلاصه‌ی هوشمند متیس اگر فعال باشد) |
| `expire_invites` / `purge_demo` / `data_delete` | انقضای دعوت‌ها، حذف حساب‌های دموی ۷ روزه، اجرای درخواست حذف داده پس از ۳۰ روز |
| `benchmarks` | میانه‌ی بی‌نام CAC صنعت (فقط وقتی حداقل ۱۰ مرچنت داده دارند) |
| `cleanup` | پاک‌سازی کش هوش مصنوعی، نشست‌های قدیمی و توکن‌های منقضی |

وضعیت آخرین اجرای هر کار در «مدیریت سامانه ← زمان‌بندی» دیده می‌شود. اجرای دستی همه‌ی کارها: `php cron.php --force`

## ۵. فعال‌سازی هوش مصنوعی (ChatGPT از طریق متیس)

۱. در پنل [metisai.ir](https://metisai.ir) یک **API Key** بسازید.
۲. در Campaign Loop با حساب مدیر وارد شوید ← منوی «پلتفرم» ← **مدیریت سامانه** ← بخش «هوش مصنوعی — متیس».
۳. ارائه‌دهنده: **متیس** · کلید API: کلید خود را وارد کنید · آدرس پایه: `https://api.metisai.ir/openai/v1` (اگر پنل متیس آدرس دیگری برای سرویس OpenAI-compatible نشان می‌دهد، همان را بگذارید) · مدل سریع: `gpt-4o-mini` · مدل دقیق: `gpt-4o` ← **ذخیره**.
۴. دکمه‌ی **«آزمون اتصال متیس»** را بزنید. پیام «اتصال برقرار است» یعنی آماده است.

> کلید در پایگاه داده با AES-256-GCM رمزگذاری می‌شود، در هیچ صفحه‌ای دوباره نمایش داده نمی‌شود و در لاگ‌ها نوشته نمی‌شود. کلید را هرگز در فایل‌ها یا چت قرار ندهید.

### متیس کجا کار می‌کند؟ (۷ وظیفه، پرامپت‌ها در پوشه‌ی `prompts/`)

| وظیفه | کجا در محصول | مدل |
|---|---|---|
| `insight_explain` | «توضیح هوشمند» زیر هر یک از ده دیدگاه | دقیق |
| `verify_narrative` | روایت علت انحراف در صفحه‌ی نتیجه | دقیق |
| `monthly_summary` | تیتر و سه بولت گزارش ماهانه‌ی ایمیلی | دقیق |
| `ask_intent` | فهم پرسش آزاد در «پرسش از داده» (محاوره‌ای، غلط املایی) | سریع |
| `ask_phrase` | بازنویسی طبیعی پاسخ عددی «پرسش از داده» | سریع |
| `csv_map` | نگاشت خودکار ستون‌های فایل CSV با سرستون‌های نامتعارف | سریع |
| `plan_reason_hint` | راهنمای مشخص‌تر کردن «دلیل انتخاب دیدگاه» هنگام ثبت طرح | سریع |

### قواعد ایمنی لایه‌ی هوش مصنوعی (خودکار)
- **هیچ عددی را مدل نمی‌سازد.** همه‌ی اعداد از موتور قطعی می‌آیند؛ «دیوار عدد» سمت سرور هر پاسخی را که عدد تازه، واژه‌ی ممنوع یا `source_ref` نامعتبر داشته باشد رد می‌کند و متن قالبی جایگزین می‌شود.
- **مدارشکن:** ۵ خطا در ۶۰ ثانیه ← ۲ دقیقه قطع موقت و استفاده از قالب‌ها.
- **سقف توکن ماهانه** برای هر فضای کاری بر اساس پلن (قابل تنظیم در مدیریت سامانه).
- **کش:** پاسخ‌های تکراری از کش خوانده می‌شوند.
- هر فراخوانی در جدول `llm_calls` ثبت می‌شود (وظیفه، مدل، تأخیر، توکن، وضعیت) و خلاصه‌اش در مدیریت سامانه دیده می‌شود.
- مالک هر فضای کاری می‌تواند در «تنظیمات» روایت هوشمند را برای فضای کاری خودش خاموش کند.

### آزمون کیفیت از خط فرمان
```
php tools/ai_eval.php          # ۳۶ پرسش ارزیابی: دقت دسته‌بندی متیس + تخلف دیوار عدد
php tools/ai_eval.php --smoke  # یک فراخوانی واقعی برای هر وظیفه
```

## ۶. ایمیل (SMTP)

مدیریت سامانه ← ایمیل: میزبان، پورت (۵۸۷ + STARTTLS یا ۴۶۵ + SSL)، نام کاربری، رمز و آدرس فرستنده را وارد و «ارسال ایمیل آزمایشی به من» را بزنید. اگر میزبان خالی بماند، از تابع `mail()` هاست استفاده می‌شود. همه‌ی ارسال‌ها در `storage/logs/mail.log` ثبت می‌شوند.

ایمیل‌ها: تأیید ایمیل، بازیابی رمز، دعوت هم‌تیمی، هشدار پایش، یادآور پایان کمپین، گزارش ماهانه، پاسخ پشتیبانی. هر کاربر در «تنظیمات» می‌تواند ایمیل‌های اعلان را خاموش کند.

## ۷. درگاه پرداخت (زرین‌پال)

- پیش‌فرض **آزمایشی** است: انتخاب پلن «رشد» بدون پرداخت واقعی ۳۰ روز فعال می‌شود (برای آزمون).
- برای پرداخت واقعی: مدیریت سامانه ← درگاه پرداخت ← «زرین‌پال — واقعی» و **مرچنت کد** را وارد کنید. قیمت به **ریال** و برچسب نمایشی قیمت همان‌جا تنظیم می‌شود.
- برای آزمون با سندباکس زرین‌پال گزینه‌ی «زرین‌پال — محیط تست» را انتخاب کنید.
- پلن‌ها: آزمایشی (۳ کمپین در ماه شمسی، ۱ کاربر) · رشد (نامحدود، ۵ کاربر، اتصال‌ها) · سازمانی (درخواست تماس ثبت می‌شود).

## ۸. اتصال ادتریس و اینترک

- در مدیریت سامانه ← اتصال‌ها، حالت **آزمایشی** فعال است: پس از اتصال با هر کلیدی، داده‌ی روزانه از روی پیش‌بینی خود کمپین ساخته می‌شود تا کل مسیر خودکار (پایش ← هشدار ← پیش‌نویس نتیجه ← تأیید) قابل آزمون باشد.
- وقتی مستندات و کلید واقعی API ادتریس/اینترک در دسترس شد، حالت را «واقعی» کنید و آدرس API را وارد کنید. قرارداد مورد انتظار: `GET {base}/ping` و `GET {base}/campaigns/{id}/stats?date=YYYY-MM-DD` با `Authorization: Bearer KEY` و پاسخ JSON شامل `spend, installs, conversions, revenue, fraud_installs, reach`.
- وب‌هوک (اختیاری): `POST /api/v1/webhooks/adtrace` یا `/intrack` با بدنه‌ی `{external_id, day, spend, …}` و هدر `X-Signature: sha256=HMAC_SHA256(body, API_KEY)`.
- کاربر در صفحه‌ی «اتصال داده» سرویس را متصل و هر کمپین در حال اجرا را با شناسه‌ی آن در سامانه‌ی مبدأ پیوند می‌دهد.

## ۹. API سرور به سرور

کلید را در «اتصال داده ← کلید دسترسی API» بسازید (فقط یک بار نمایش داده می‌شود).

ثبت نتیجه‌ی کمپین (پیش‌نویس برای تأیید؛ با `"confirm": true` مستقیم ثبت می‌شود):
```bash
curl -X POST https://your-site/api/v1/results \
  -H "Authorization: Bearer sk_loop_…" -H "Content-Type: application/json" \
  -d '{"plan_code":"plan-1405-101","rows":[{"channel":"گوگل","segment":"کاربر جدید","spend":120000000,"installs":2400,"conversions":180}],"fraud_pct":3,"window_days":7}'
```
ردیف‌ها باید با تخصیص طرح یکی باشند. پاسخ: کد اجرا، علت محتمل انحراف، امکان کالیبراسیون و `source_ref`.

خواندن زنجیره‌ی شناسه و گزارش: `GET /api/v1/campaigns/plan-1405-101`

محدودیت: ۱۲۰ درخواست در دقیقه برای هر کلید.

## ۱۰. Nginx (به‌جای Apache)

```nginx
server {
    listen 443 ssl http2;
    server_name loop.example.com;
    root /var/www/campaign-loop;
    index index.php;
    client_max_body_size 5m;

    location ~ ^/(app|database|storage|tests|prompts|tools)(/|$) { deny all; return 404; }
    location ~ /(config\.php|config\.sample\.php|README.*|.*\.md|.*\.sql)$ { deny all; return 404; }
    location ~ /\. { deny all; }

    location / { try_files $uri $uri/ /index.php?$query_string; }

    location ~ \.php$ {
        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        fastcgi_param HTTP_AUTHORIZATION $http_authorization;
        fastcgi_pass unix:/run/php/php8.1-fpm.sock;
    }
    location ~* \.(woff2|png|jpg|svg|css|js)$ { expires 30d; access_log off; }
}
```

## ۱۱. امنیت پس از نصب

- [ ] پوشه‌ی `install` حذف شد.
- [ ] سایت روی **HTTPS** است (cPanel ← SSL/TLS Status ← AutoSSL).
- [ ] در `config.php` مقدار `debug` برابر `false` است.
- [ ] مجوز `config.php` روی `640` یا `600`؛ پوشه‌ی `storage` قابل نوشتن (`755` یا `775`).
- [ ] رمز پیش‌فرض عوض شد و برای حساب مدیر **ورود دومرحله‌ای** (صفحه‌ی امنیت) فعال شد.
- [ ] پشتیبان‌گیری روزانه از پایگاه داده (cPanel ← Backup).

محافظت‌های داخلی: CSRF روی همه‌ی فرم‌ها، رمز عبور argon2id/bcrypt، محدودیت تلاش ورود، نشست‌های قابل لغو، هدرهای امنیتی، رمزگذاری کلیدها، کنترل نقش سمت سرور (`can(role, action)`) و ثبت همه‌ی تغییرات در «لاگ تغییرات».

## ۱۲. عیب‌یابی

| مشکل | راه‌حل |
|---|---|
| خطای ۵۰۰ یا «خطای داخلی» | فایل `storage/logs/php-error.log` و `storage/logs/app-*.log` را ببینید. موقتاً `debug => true` جزئیات را نشان می‌دهد. |
| همه‌ی صفحه‌ها ۴۰۴ | `mod_rewrite` فعال نیست ← `'pretty_urls' => false` |
| حروف فارسی به صورت `؟؟؟` | collation پایگاه داده باید `utf8mb4_unicode_ci` باشد؛ فایل SQL را در پایگاه داده‌ی جدید با همین collation وارد کنید. |
| «app_key in config.php is not set» | در `config.php` یک کلید ۶۴ کاراکتری هگز بگذارید (بخش ۳ب). |
| آزمون متیس: خطای اتصال یا timeout | هاست اتصال خروجی به `api.metisai.ir` را مسدود کرده؛ از پشتیبانی هاست بخواهید باز کند. آدرس پایه و اعتبار کلید را در پنل متیس بررسی کنید. تا رفع مشکل، محصول با متن‌های قالبی کار می‌کند. |
| ایمیل نمی‌رسد | SMTP را در مدیریت سامانه تنظیم کنید؛ پوشه‌ی Spam را ببینید؛ `storage/logs/mail.log` |
| یادآورها و گزارش ماهانه ارسال نمی‌شوند | کران‌جاب تنظیم نشده (مدیریت سامانه ← زمان‌بندی) |
| نصب‌کننده: «جدول‌های دیگری دارد» | پایگاه داده متعلق به برنامه‌ی دیگری است؛ یک پایگاه داده‌ی خالی بسازید. |
